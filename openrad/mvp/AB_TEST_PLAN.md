# TerryClash 短时停用对照测试

状态：2026-11-23 已完成用户手动停止 TerryClash 后的 60 秒测试，目标仍为认证 Relay；未获得 P2P。测试结束已清理 OpenRad 临时环境，TerryClash 保持停止。随后又完成被动角色、随机端口及早期构建对照，并按用户要求移除路由器全部 OpenRad 实验环境。详见 [最新交接](HANDOFF_2026-11-23.md) 和 TEST_RESULTS.md。下文保留原先自动停用/恢复的计划与此前执行拦截记录。

## 对照依据

用户确认物理路由宿主机上的官方 Radmin 客户端直接连接光猫，未经过 ImmortalWrt。最新截图显示它与外部客户端为 UDP/NAT 直连、约 11 ms。因此当前两端确实具备官方客户端 P2P 条件，不能根据此前短暂的中继状态断言光猫或外部网络不支持 P2P。

外部客户端通过物理宿主机的远程桌面，再进入当前工作电脑。不得重启物理宿主机、操作它的 Radmin 或网卡、修改光猫。测试只涉及 ImmortalWrt 中的 TerryClash 和独立 OpenRad 实例。

## 目的与影响

短暂停止 TerryClash，重新触发 OpenRad 与已确认外部成员的协商，观察 Direct TCP、Direct UDP 或 Relay。比较 TerryClash 开启与关闭时的候选地址、WAN 打洞包、回包和认证结果。

预计代理及其 DNS 接管暂停约 60 秒，随后恢复。依赖 TerryClash 的网页、应用和当前 Codex 网络连接可能短暂中断。物理宿主机到光猫的官方 Radmin 路径不在变更范围内；测试前仍需确认实际远程管理路径。

## 执行前条件

1. 用户明确同意此短时中断，已满足。同一测试范围内沿用该授权，不重复询问。执行环境的工具许可仍必须满足，不得绕过自动审批。
2. 核对 TerryClash 正在运行、UCI enabled 为 1、当前配置有效、原策略组选项可保存和恢复。
3. 核对 OpenRad 实例仍在线，自动清理计时不会在测试中途到期。若已被清理，先评估恢复既有实例所需资源，不部署被拦截的新二进制。
4. SSH 管理走 LAN 直连；记录原始服务、DNS、策略路由、配置校验值及当前代理选择。
5. 预先启动独立于 SSH 和 Codex 会话的 60 秒恢复任务，并验证其进程存活；恢复任务必须在停止 TerryClash 之前就位。

## 测试顺序

1. 记录开启状态下的目标成员连接方式、当前实例 PID、版本和摘要。
2. 安排独立恢复任务。恢复任务通过 `/etc/init.d/terryclash start` 恢复原服务，并验证 Mihomo API、透明接管、DNS 和原策略组选项；必要时进行有限次数重试，保留日志。
3. 通过 `/etc/init.d/terryclash stop` 暂停服务，不使用会修改 UCI enabled 的管理命令，不删除用户配置。
4. 重启当前已部署的 OpenRad 实例，仅重建它自己的连接；主网络试验模式须移除该实例自动添加的组播及全局广播路由，保留分配的虚拟网段路由。
5. 在剩余测试窗口观察认证通道和 WAN 包，执行虚拟地址通信。测试不操作外部主机上的现有远程桌面连接。
6. 测试结束立即恢复 TerryClash；无论主测试是否失败或 SSH 是否断开，独立恢复任务仍按时执行。
7. 核对原服务、DNS、IPv4/IPv6 接管和策略组选择，比较配置校验值。收集结论后继续保留 OpenRad 的限时清理保护。

## 结果判定

- 只有停用 TerryClash 时建立认证 P2P：继续定位其具体干扰路径，不直接把停用服务作为长期方案。
- 开启与关闭时均中继：当前 OpenRad 的协议、协商角色和套接字实现仍需排查，不能声称问题已经由停用代理解决。
- 无论路径为何，都必须验证实际数据往返，不能只用图标或成员在线状态判定。
